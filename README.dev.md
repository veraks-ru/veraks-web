# Локальный запуск кластера

Фронтенд (Next.js) + бэкенд (FastAPI) + воркер (ARQ) + Postgres + Redis + мок ЕСИА.

## Вариант A — всё в Docker (как поедет в k8s)

Требует доступа к Docker Hub и PyPI (CI, обычная машина, кластер):

```bash
docker compose --profile full up --build
```

Поднимает postgres, redis, backend (мигрирует и стартует), worker, mock-esia,
frontend. Открыть http://localhost:3000.

> Postgres здесь же заводит «из коробки» непривилегированную роль приложения
> `orakul_app` (init-скрипт `dev/postgres-initdb/`, второй контур защиты
> append-only-журналов — см. `backend/README.md`). `DATABASE_URL` приложения
> локально остаётся под владельцем (`orakul`) — проще для дева; роль нужна
> только для ручной/e2e-проверки REVOKE.

> В этой песочнице Docker Hub и PyPI недоступны (DNS/handshake блокируются),
> поэтому образы приложения здесь не собрать. Артефакты (Dockerfile'ы, compose)
> корректны и собираются там, где сеть открыта. Локально используйте вариант B.

## Вариант B — данные в Docker, приложение на хосте

```bash
# 1. Слой данных
docker compose up -d                      # postgres + redis (локальные образы)

# 2. Бэкенд + воркер + мок ЕСИА (из .venv бэкенда)
cd ../backend
python -m venv .venv && . .venv/bin/activate && pip install -e .   # один раз
set -a && . ./.env && set +a              # переменные окружения
alembic upgrade head                      # миграции (все, включая billing)
python seed.py                            # демо-данные + скоринг
uvicorn app.main:app --port 8000 --reload &
arq app.worker.WorkerSettings &           # фоновые задачи (скоринг, roll сезонов)

cd ../web/dev/mock-esia
../../../backend/.venv/bin/uvicorn app:app --port 9000 &

# 3. Фронтенд
cd ../../ && npm install && npm run dev    # http://localhost:3000
```

## Вход в локальной разработке

Сейчас включён только email-вход: флаг `AUTH_PROVIDERS=email` в
`docker-compose.yml` (переменная бэкенда `.env` при варианте B) выключает
ЕСИА — договор с интегратором ещё не заключён. Код и мок ЕСИА никуда не
делись, включаются обратно добавлением `esia` в список провайдеров через
запятую (`AUTH_PROVIDERS=email,esia`).

### Email + одноразовая ссылка (magic link)

1. На экране входа указать email → «Отправить ссылку». Бэкенд отвечает
   `202` всегда, независимо от того, зарегистрирован ли такой email
   (`POST /auth/email/request`, анти-энумерация аккаунтов).
2. Открыть веб-интерфейс **mailpit** — http://localhost:8025 — письмо с
   ссылкой входа приходит туда вместо реальной отправки (в варианте B
   бэкенд на хосте шлёт SMTP на `localhost:1025` без логина/пароля/TLS).
3. Перейти по ссылке из письма — фронт обменивает одноразовый токен на
   сессию (`POST /auth/email/callback`). Ссылка живёт 15 минут и одноразовая:
   повторный переход или устаревшая ссылка вернут ошибку входа.

Новый email создаёт новый аккаунт (`username` вида `predictor-<hex>`
генерируется автоматически, `identity_verified=false` — в отличие от входа
через ЕСИА, личность государственной идентификацией не подтверждена) и ведёт
на онбординг (согласия). Повторный вход тем же email возвращает в тот же
аккаунт.

### Вход через мок ЕСИА (сейчас выключен флагом)

Код и dev-мок сохранены для повторного включения ЕСИА, но при
`AUTH_PROVIDERS=email` соответствующие эндпоинты (`/auth/esia/login`,
`/auth/esia/callback`) недоступны, а витрина не показывает кнопку входа
через ЕСИА. Ниже — как это работает, когда провайдер включён.

«Войти через Госуслуги» → мок-страница выбора учётной записи
(http://localhost:9000/authorize). Засеянные граждане:

- **kalibr** → @kalibr, роль **admin**, есть история;
- **mediana** → роль **admin** (нужен второй админ для подтверждения выплат);
- **baseline** → роль **arbiter**;
- «Новый гражданин» → свежий аккаунт (роль user);
- «Отказаться» → возврат с `error=access_denied` (проверка экрана «Вход отменён»).

Уникальность «1 человек = 1 аккаунт» — по хэшу СНИЛС.

После первого входа любой демо-пользователь попадает на онбординг
(`/onboarding`) — один экран с согласиями: оферта и обработка ПДн (152-ФЗ).
Пока они не подтверждены, участие в конкурсе закрыто и на сервере: прогноз и
предложение события вернут `403 ConsentRequiredError`. Версии документов
задаются в `.env` бэкенда (`CONSENTS_OFFER_VERSION`/`CONSENTS_PDN_VERSION`) —
подняв версию, можно проверить, что экран согласий возвращается.

Мок повторяет боевой OIDC-поток: PKCE (S256), `nonce` и подписанный
`id_token` (ключ RS256 генерируется при старте мока, публичная часть — на
http://localhost:9000/jwks). Чтобы бэкенд проверял маркер, в его `.env`
должны быть `ESIA_ISSUER=http://localhost:9000` и
`ESIA_JWKS_URL=http://localhost:9000/jwks` (в `docker compose --profile full`
уже прописаны). Вне `APP_ENV=local` пустой `ESIA_JWKS_URL` не даст бэкенду
стартовать.

## Админка (`/admin`)

Доступна ролям editor/arbiter/admin (в шапке появляется ссылка «Админка»).
Войдите как **kalibr** и откройте http://localhost:3000/admin:

- **События** — создать (черновик) → опубликовать → закрыть приём → зафиксировать
  исход → посчитать Brier; редактирование, отмена, решения по спорам.
- **Сезоны** — создать → активировать (демо-пороги) → финализировать.
- **Призовой фонд** — завести фонд, внести депозит, создать выплату; подтверждение
  выплаты — **другим** админом (maker-checker): войдите как **mediana** и подтвердите.

Окно оспаривания локально = 0ч (`RESOLUTIONS_DISPUTE_WINDOW_HOURS`), поэтому
«Разрешить → Посчитать» срабатывает сразу.

Полный цикл проверяется на ходу: создать → опубликовать → (спрогнозировать как
участник) → закрыть приём (прогнозы замораживаются) → разрешить → посчитать
Brier → результат на публичной странице и в лидербордах.

## Что подключено к реальному API

Лента, экран прогноза (PUT), авторизация ЕСИА (cookie-сессия), `/auth/me`,
лидерборды (global/категории/сезон с резолвингом имён по `user_id`), профиль
(калибровка/ранг/категории/история), разрешённое событие, шеринг, сезоны.

Базовый URL бэкенда — `NEXT_PUBLIC_API_BASE` (`.env.local`, по умолчанию
`http://localhost:8000`).

`SITE_URL` (`.env.local`, по умолчанию `http://localhost:3000`) — публичный
адрес самого фронта. Он же `metadataBase`: база для абсолютных ссылок на
OG-картинки событий (`/events/[slug]/opengraph-image`). Переменная **без**
префикса `NEXT_PUBLIC_` — читается только на сервере, в бандл не попадает и в
проде задаётся окружением контейнера, без пересборки образа. Кривое значение
не роняет сайт: будет предупреждение в лог и откат на localhost.

## Заметки

- Сводку толпы бэкенд скрывает до закрытия приёма (строже, чем по-юзерно) —
  на открытых событиях консенсус показывается после закрытия.
- Сезонная лига пуста: демо-события не привязаны к сезону (можно привязать
  в `seed.py`).
